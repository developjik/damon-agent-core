# ADR-0001: 구현 언어로 Rust를 선택한다

- Status: Accepted (코드로 실현됨 — 단일 크레이트 `damon-core` 0.8.0)
- Date: 2026-09 (스캐폴드 `811c8d5`, 파운데이션 `06b507c`)

## Context

damon-core는 상주(resident) 로컬 데몬이다: macOS·Linux·Windows에서
에이전트 CLI 자식 프로세스를 스폰·감독하고, WebSocket으로 다수
클라이언트에 이벤트를 팬아웃하며, SQLite에 세션 기록을 쌓는다.
요구 조건:

- 자식 프로세스 트리를 확실히 회수할 것(Unix 프로세스 그룹 시그널,
  Windows Job Object kill-on-close)
- OS 네이티브 자격증명 저장소(keychain/DPAPI/secret-service)
- 배포물이 단일 바이너리 — 외부 런타임·라이브러리 의존 없이 설치
- 동시 다중 세션·다중 클라이언트의 비동기 I/O

## Decision

단일 Rust 크레이트로 구현한다. workspace 분할 없이 라이브러리
(`src/lib.rs`의 flat `pub mod`) + 얇은 바이너리(`src/bin/` 6개)
구조. edition 2024, `rust-version = "1.95"`, `rust-toolchain.toml`이
toolchain 1.95.0 + rustfmt + clippy를 핀한다.

## Consequences

- `rusqlite`의 `bundled` feature로 SQLite를 정적 포함 — 설치 대상에
  시스템 sqlite가 없어도 된다 (Cargo.toml `[dependencies]`).
- 프로세스 하드닝이 실제로 이뤄졌다: `windows-sys`의 JobObjects
  feature(Cargo.toml target deps)와 Unix `libc` 프로세스 그룹
  시그널(`src/backend/transport.rs` 주석).
- 119개 커밋 / `src` 45,982줄(tests·examples 포함 60,609줄)이 단일
  크레이트에서 운영 가능함이 입증됐다. 대신 전체 재빌드 비용과
  크레이트 내부 의존 규율은 리뷰로 관리한다.
- 프로덕션 코드의 unsafe는 6파일 9곳에 분포한다 — `registry.rs:329`
  (Windows 레지스트리 PATH 재읽기 `RegGetValueW`), `transport.rs`
  92/118/325/631 (Windows Job Object 핸들 + Unix `libc::kill`
  프로세스 그룹 종료), `mcp_inventory.rs:1022`와
  `cli_lifecycle.rs:166` (자식 프로세스 트리 kill — `libc::kill`
  프로세스 그룹), `config.rs:349` (`dotenvy`를 통한
  `std::env::set_var` — edition 2024부터 env 변경은 unsafe),
  `skills_hub/discover.rs:78` (`MaybeUninit::assume_init` — scoped
  병렬 슬롯). 각 위치는 `#[cfg]` 게이트 또는 SAFETY 주석으로 경계가
  명시돼 있다.
- Node(`npm/` zero-dep 클라이언트)·Python(`python/` SDK)은 Rust를
  대체하는 게 아니라 wire 계약을 미러링하는 클라이언트 계층으로
  남는다.
